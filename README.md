# CRM Backend — Spring Boot 4.1 · Hibernate · MySQL · Modulith · Flyway

REST API for the Persian React CRM (Vtiger 7 inspired). 27 modules, DTO-based, JWT security,
Persian validation/exception messages, Jalali-aware reports.

| | |
|---|---|
| Runtime | Java 21 (works on 25), Spring Boot **4.1.1**, Spring Modulith **2.1.1**, Hibernate ORM (managed by Boot) |
| Database | MySQL 8.4, schema owned by **Flyway** (`ddl-auto=validate`) |
| Security | Spring Security, stateless HS256 JWT, per-endpoint `@PreAuthorize("hasAnyAuthority('*','leads:view')")` |
| Docs | Swagger UI at `/swagger-ui.html`, Modulith diagrams generated by `ModularityTests` into `target/spring-modulith-docs` |

## Run
```bash
docker compose up -d mysql
SPRING_PROFILES_ACTIVE=dev mvn spring-boot:run        # admin / admin123 (dev profile only)
mvn test            # unit tests + Modulith structure verification (no database)
mvn verify          # + integration tests (*IT) on a throw-away MySQL via Testcontainers (needs Docker)
```
Frontend: set `VITE_USE_MOCK=false` in the React app; Vite proxies `/api` to `localhost:8080`.

Production needs `JWT_SECRET` (≥ 32 chars), `DB_URL/DB_USERNAME/DB_PASSWORD`, `CORS_ALLOWED_ORIGINS`;
optionally `BOOTSTRAP_ADMIN_PASSWORD` for the first-run `admin` user (only if the users table is empty).

## Modular structure (Spring Modulith)
```
ir.crm
  shared        OPEN kernel: BaseEntity, error model + GlobalExceptionHandler, AbstractCrudService,
                QueryRules/SpecificationFactory, LookupProvider SPI, RecordChangedEvent, Jalali utils
  identity      users, roles (+ permission matrix), teams, JWT auth, security config, admin bootstrap
  sales         leads, contacts, organizations, opportunities, quotes, sales orders, invoices,
                purchase orders, service contracts  (+ lead conversion workflow)
  catalog       products, services, price books, vendors, inventory, assets
  marketing     campaigns            support   cases, FAQ
  projects      projects, tasks      productivity   tasks, events, e-mails, documents
  activity      per-record timeline built from events (async, Modulith event publication registry)
  reporting     dashboard, analytics, 8 reports (plain SQL; reads other modules' tables, never their classes)
```
Rules enforced by `ModularityTests`: every module may depend only on `shared`; modules reference each other
**by id only** and resolve labels/validate references through the `LookupProvider` SPI.
Cross-module reactions use events (`RecordChangedEvent` → `activity`).

## API contract (matches the React app)
`GET /api/v1/{module}?page&pageSize&search&sortField&sortOrder=ascend|descend&{field}=…` → `{items,total,page,pageSize,totalPages}`
`GET|PUT|DELETE /{module}/{id}` · `POST /{module}` (201) · `POST /{module}/bulk-delete` · `GET /{module}/lookup?search&limit`
`GET /{module}/{id}/activities` · `POST /leads/{id}/convert` · `GET|PUT /roles/{id}/permissions` · `PUT /users/{id}/password`
`POST /auth/login|change-password` · `GET /auth/me` · `GET /dashboard|analytics|reports|reports/{id}?period=month|quarter|year`

DTO naming: `{Entity}CreateRequest`, `{Entity}UpdateRequest`, `{Entity}Response` (records, Bean Validation on requests).
Lookup fields are **ids in requests** and `{id,label}` in responses; selects are lowercase keys (`"in_progress"`),
dates are ISO Gregorian (`2026-10-09`); Jalali is a presentation concern.

## Errors (Persian) — one shape everywhere
```json
{ "timestamp": "…", "status": 400, "code": "VALIDATION_FAILED", "message": "اطلاعات ارسال‌شده نامعتبر است…",
  "path": "/api/v1/leads", "errors": { "name": ["این فیلد الزامی است"] },
  "violations": [ { "field": "name", "label": "نام و نام خانوادگی", "message": "این فیلد الزامی است" } ] }
```
Codes (`ErrorCode`): VALIDATION_FAILED, MALFORMED_REQUEST, INVALID_PARAMETER, UNAUTHORIZED, INVALID_CREDENTIALS,
ACCOUNT_DISABLED, ACCESS_DENIED, RESOURCE_NOT_FOUND, ROUTE_NOT_FOUND, METHOD_NOT_ALLOWED, DUPLICATE_RESOURCE,
REFERENCE_IN_USE, INVALID_REFERENCE, CONCURRENT_MODIFICATION, BUSINESS_RULE_VIOLATION, INTERNAL_ERROR …
Security-filter failures (401/403) are routed through the same `@RestControllerAdvice`; 500s return only a `traceId`.
Messages live in `messages.properties` (hand-written), `messages-fields.properties` and `messages-enums.properties`
(generated). Bean Validation's default messages are overridden in Persian, and the locale is fixed to `fa`.

## Generated code
`tools/modules.json` is an export of the React app's module registry. `python3 tools/generate.py` regenerates
entities, DTOs, enums, mappers, services, controllers, lookup providers, `V2…V7/V9` migrations, `ModuleCatalog`
and the field/enum message bundles for the 24 data modules (+ controllers for users/roles/teams).
Files are plain Java and may be edited by hand; re-running overwrites them. Add a module by adding it to the
registry, re-exporting the JSON and running the generator.

## Security notes
- Permissions are `{module}:{view|create|edit|delete|export}`; role kind `ADMIN` carries `*`. They are embedded in the JWT at login,
  so changes apply at next login (default token lifetime 8 h).
- Users created without a password get an unusable random one until an admin calls `PUT /users/{id}/password`.
- Not included (add for production): login rate-limiting, refresh tokens/revocation, file storage for documents, e-mail sending.
